# Chinese Text Wrapping

## Reproduction And Fix

The mixed Chinese/English progress paragraph in `cjk-wrapping.test.ts` previously
rendered a second row containing only 16 content cells in an 80-column terminal.
The old wrapper recognized ASCII spaces only. It moved an unspaced Chinese run
to the next row before splitting it, leaving most of the preceding row unused.

The shared ANSI wrapper now uses `linebreak` 1.1.0 to find Unicode break
opportunities inside non-ASCII tokens. Breaks must also be grapheme boundaries
from Node's `Intl.Segmenter`. Source offsets preserve ANSI styling and OSC 8
hyperlinks across the newly available boundaries. ASCII-only tokens and explicit
newlines retain their existing behavior.

The same second row now uses 77 content cells, plus the two-column message
indent. All non-final rows of the reproduction leave at most three cells unused
at 60/80/100/120 columns. The paragraph remains left-aligned; no justification
spaces are inserted between words or Chinese characters.

## Codex Comparison

The local `codex-main/codex-rs` snapshot renders ordinary prose with
`markdown_render.rs::flush_current_line` and `wrapping.rs::adaptive_wrap_line`.
Its default `RtOptions` uses `textwrap` word separation with Unicode line-break
support. Both implementations wrap prose at valid boundaries and preserve style
information; neither expands character spacing to justify body text.

Mycli retains its existing ASCII word/URL wrapping policy. The chosen JavaScript
library ships Unicode 13 line-break data; Node supplies newer grapheme safety.
This is a focused Chinese wrapping fix, not a claim of identical Unicode tables
or URL wrapping behavior with Codex. The reference is a local source snapshot,
not a verified latest release.

- Unit tests cover remaining-row usage, Chinese punctuation, ANSI-separated
  combining marks, emoji clusters, OSC 8 links, and unchanged ASCII wrapping.
- The user's paragraph is checked against concrete expected rows, then streamed
  character by character and resized at 60/80/100/120 columns.
- Physical terminal-cell tests inspect every streamed update before any resize,
  native and ordinary resize, and SGR foreground colors across continuation rows.
- Streamed punctuation, mixed words, rich Markdown, and grapheme boundaries
  match fresh rendering at 3/4/7/8/13/18/40 columns.
- All 40 focused cases passed, including 10 added regression cases.
- `npm test --ignore-scripts` passed 359 files in 180.7 seconds: 302 unit,
  22 contract, 29 integration, 5 platform, and 1 release test file.
- Build, lint, all workspace type checks, contract/config drift, release
  verification, and `git diff --check` passed. A local declaration for the
  untyped dependency is explicitly referenced so source-condition consumers
  also receive its types.
- An isolated `npm ci --ignore-scripts --offline` restored the five packages
  from the exact new root-lockfile entries, and the installed breaker ran
  successfully outside the workspace dependency tree.

The app manifest mirrors the TUI dependency because release packaging vendors
internal workspace code. Existing versionless optional ripgrep lock records
caused npm's root installer to fail with `Invalid Version`. The new dependency
subtree was generated by npm in an isolated directory and merged into the root
lockfile with its registry URLs and integrity hashes; unrelated records were
preserved.
