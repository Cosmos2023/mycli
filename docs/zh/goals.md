# 会话目标

[English](../goals.md) | **简体中文** | [中文目录](README.md)

目标是附属于会话、可持久保存的一项任务。即使助手的一轮回复已经结束，目标也可以继续保持活动状态，由后端启动下一个普通轮次。执行任务的模型负责验证结果，并调用 `update_goal` 完成目标。这个过程不需要额外的评估模型或 MCP 服务器，也不会隐式创建目标或设置隐藏的轮次数上限。

<a id="controls"></a>

## 控制方式

| 命令 | 行为 |
| --- | --- |
| `/goal <objective>` | 创建活动目标，会话空闲时开始执行 |
| `/goal --tokens <n> <objective>` | 创建目标，并明确指定正数 token 预算 |
| `/goal` | 查看目标、状态、已报告用量、耗时及控制方式 |
| `/goal pause` | 停止自动继续，并中断正在执行的轮次 |
| `/goal resume` | 恢复已停止的目标，重新开始检查阻塞条件 |
| `/goal edit <objective>` | 替换目标，使旧轮次失去更新目标的权限，并重置阻塞检查 |
| `/goal budget <n>` | 设置正数总预算，保留已消耗的 token 计数 |
| `/goal budget off` | 移除 token 上限 |
| `/goal clear` | 移除当前目标并中断相关执行，保留对话历史 |

编辑活动目标会使当前目标轮次失效，下一个获准执行的轮次使用编辑后的目标。编辑已停止的目标后，它会保持暂停，直到用户明确恢复。编辑已完成的目标会将其重新设为暂停，并保留用量。需要全新的预算和标识时，可以在完成后创建新目标，或先清除旧目标。

本地工具包括 `create_goal({ objective, token_budget? })`、`get_goal({})` 和 `update_goal({ status })`，仅向交互式根运行时开放。模型只能根据用户明确表达的意图创建目标；可以将目标标记为完成或阻塞，也可以在用户明确要求时暂停。恢复和预算编辑由用户控制。未完成的目标不能被静默覆盖。理解自然语言意图、判断完成证据是模型的责任，不由确定性分类器代替。

<a id="status-and-execution"></a>

## 状态与执行

| 状态 | 含义 |
| --- | --- |
| `active` | 会话空闲时可以继续执行 |
| `paused` | 用户中断、明确暂停或恢复执行状态后，需要手动恢复 |
| `blocked` | 模型报告无法推进，或轮次发生终止性执行错误 |
| `usage_limited` | Provider 配额已耗尽 |
| `budget_limited` | Token 预算已用完，或无法确定有预算目标的用量 |
| `complete` | 执行模型已验证目标并报告完成 |

后端要求本次执行至少经过三个目标轮次，才接受模型报告的阻塞状态。模型还必须确认：连续出现的是*同一个*阻塞条件，而且已经没有可以独立推进的有效工作。恢复会重置这项检查，但不会重置用量。执行错误会立即停止目标，并沿用现有错误和重试体系。

用户的后续消息、执行中补充的指令、交互请求和会话切换优先于自动启动。目标执行复用现有的会话执行权、轮次预留、provider 重试、工具策略和 Worker 租约。重复的空闲通知不会启动两个轮次。目标 ID 和修订号可防止旧轮次修改已替换或恢复的目标。目标不会授予额外的文件、网络或审批权限。

输入框上方的工作摘要显示 Goal 状态；空间允许时还会显示 token 用量和对应的 `/goal` 控制命令。它与任务进度、后台 Shell 数量共用一行，即使关闭会话页脚也会显示。完整记录可通过 `/goal` 查看。自动轮次显示为“Continuing goal”，重新加载历史后也是如此，不会被渲染成新的用户消息。仅关闭弹窗不会暂停目标；真正的中断会先暂停目标，再按正常取消流程释放执行状态。

<a id="accounting-and-recovery"></a>

## 用量统计与恢复

目标 token 用量等于未命中缓存的输入（包括缓存写入）加输出，不计缓存读取。这是 token 预算，不是费用估算。统计前会统一不同 provider 的缓存用量格式。每次 provider 尝试的用量检查点都是累计值，并与目标及审计事件一起原子提交，因此重复观测和重放不会重复计费。可归属于目标的子 Agent 工作和上下文压缩也计入用量。在轮次中创建目标时，统计基线从创建时开始；此前发起、促成目标创建的请求不计入。

每次子 Agent 执行都会单独记录发起它的目标，因此后来为新目标复用空闲 Agent 时，不会沿用旧目标的用量归属。父轮次结束后仍保留其引用，供延迟启动的子 Agent 使用。

预算限制在可观测的模型步骤边界生效。已经发出的请求或重试可能在到达边界前超出预算。执行仍受普通 provider 和 Agent 限制约束。缺失用量会标记为 `usage_incomplete`；显示值只是下限，有预算的目标会停止，而不是假定这些执行免费。如果目标保存失败，自动启动会停止，取消操作仍会释放当前轮次及其执行状态。

耗时覆盖实际执行的目标轮次，不包含进程停止期间或轮次之间的空闲时间。读取和结算会刷新已观测的耗时；UI 计时器不负责决定执行状态。

目标保存在格式为 15 的会话数据库中。打开格式 12、13 或 14 的运行时数据库时，会在事务内升级，不会重写对话历史。旧版本必须拒绝格式 15；回退时应使用数据库备份。`session_goal` 保存当前快照，`session_goal_usage` 保存累计用量检查点，对模型不可见的目标活动记录保留审计信息。清除目标会删除当前快照，但保留历史。

冷启动恢复时，原本活动的目标会保持暂停。分叉会话继承分叉边界处的目标快照，但获得新的标识，并停止执行。重新连接仍在运行的后端时，显示其实际执行状态。清理操作会保留只有目标的会话。上下文压缩通过保留的上下文恢复目标；实时用量更新不会重写先前的 provider 请求，也不会反复修改系统提示词。

退出 mycli 后，目标不会继续以守护进程或定时任务形式运行。无界面的 `exec` 和 `review` 保持原有的单轮结束约定。
